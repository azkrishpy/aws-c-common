# Simulated changelog history

Two branches, generated by `.github/scripts/simulate-live.sh` on the `changelog-selftest` branch. Every edit to `CHANGELOG.md` and every archive here was made by `changelog.py` and `docs-replay.sh` — nothing was hand-written. If something looks wrong, the tool is wrong.

- **`sim-1x`** — the release branch, as `main` would look.
- **`sim-1x-docs`** — the docs branch, as `docs` would look.

No tag, no GitHub Release, no artifact. Nothing outside these two branches was touched.

## What it contains

18 commits on top of `main`: 13 merged pull requests and 5 releases, dated across the last four weeks.

| Release | Contains |
|---|---|
| 1.0.2 | a feature and a fix |
| 1.1.0 | a breaking change, a fix, a note |
| 1.1.1 | a fix |
| 1.2.0 | a breaking change, a feature, a revert, two notes |
| 1.2.1 | a fix (its chore renders nowhere) |

1.1.0 and 1.2.0 each opened a new minor line, so each archived the line before it. Two pull requests (#1294, #1295) are merged but unreleased, so they appear only on the docs branch.

## Things worth judging

- **`.changes/` holds four files:** two unreleased fragments and two archived lines. A released fragment is deleted once rendered, so fragments never pile up.
- **The root holds only the line being released into** — 1.2.x — and links the closed lines under Earlier releases. No release rewrites an older section.
- **The unreleased region on the release branch is one link**, straight to the docs branch's rendered file. The docs branch carries the list itself.
- **`1.0.x.md` and `1.1.x.md` were moved, not re-rendered.** The sections are the same text with one more `..` in each link, because an archive sits a directory deeper.
- **The hand-written `## [1.0.0]` section travelled with its line** into `1.0.x.md`. That is the adoption path: pre-existing history belongs to the line it shipped in.
- **A `chore` never appears.** #1285 and #1293 were chores; 1.2.1 shows only its fix for that reason.
- **A breaking change appears once.** #1289 is a `feat` carrying the `minor` label, so it renders under Possible Breaking Changes and not under Features. The label settles that, not the ABI check, and nothing about it is stored in a fragment.
- **`git diff --name-only sim-1x sim-1x-docs` is just `CHANGELOG.md`** — the docs branch differs from the release branch only by its unreleased region.
- **1.0.1 has no entry.** It shipped before fragments existed, and nothing backfills it.

## Regenerating

```sh
git fetch origin
bash <(git show changelog-selftest:.github/scripts/simulate-live.sh) \
  <sim-branch> <docs-branch> main changelog-selftest
```

The generator refuses to run if the docs branch already exists on `origin`, because `docs-replay.sh` prefers a remote docs branch and would replay onto the previous run's state.
